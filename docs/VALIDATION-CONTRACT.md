# Native saved-report validation

This increment invokes the unchanged preserved Python `ValidationEngine.Cli` on an exact-byte copy of the host-selected successful execution report. It does not rerun backtests. Engine-level stress and walk-forward evidence remain missing, so a completed process is not a trading validation PASS. The original verdict vocabulary is PASS, FAIL and UNPROVEN; report-only acceptance requires the latency-stress and walk-forward missing-evidence labels and rejects a false PASS. A legitimate FAIL remains FAIL with its missing evidence visible.

Commands: `validation_run({request:{runId,monteCarloRuns?,seed?,gates?}})`, `validation_cancel()`, `validation_last_good_result()`. Settings have bounded numeric validation and no renderer-provided filesystem or command paths. Monte Carlo runs are 1–100000 (default 1000), seed 0–2147483647 (default 42). Default retained gates are minimum trades 30, profit factor 1.15, maximum drawdown 10%, daily drawdown 3%, survivability 0.8. Retained report-only perturbation defaults are skip 5–20%, slippage 2 pips and PnL noise 10%; these are validation assumptions, not changes to the saved execution.

The project/run/success identity, exact canonical run containment and immutable completion hash use the same verifier as Reports. The host copies original JSON into a unique app-owned validation directory, writes absolute config paths, sets `RunBacktests=false`, and passes only that frozen source in `ExistingReports`. It checks the copy's hash again after Python finishes. No missing starting capital or project identity is replaced with invented trading values.

Runtime priority is bundled `runtimes/python/python.exe`. Debug builds additionally allow explicit `BACKTEST_PYTHON` or PATH and `BACKTEST_VALIDATION_SRC`; no Codex runtime path is embedded. The fixed app-owned `-I -B -X utf8 -c` output wrapper inserts the explicit package root from a separate argv entry, runs `ValidationEngine.Cli` once with `runpy`, and then adapts its fixed native output directory. This works when embeddable Python `_pth` ignores `PYTHONPATH`; it neither interpolates renderer code nor depends on site packages. The staging script copies and hashes 27 unchanged package Python files into `resources/validation`.

Only one validation job may run. Cancellation/timeout drops and kills the direct Python process; stdout/stderr are bounded to 64 KiB each before accumulation. The overall limit is 600 seconds. Report-only mode spawns no dotnet children. Future engine rerun modes require process-tree cancellation before they can be enabled. An RAII guard clears cancel/latch state on all exits. Failed/canceled jobs preserve prior completed session evidence. Results remain visible only for the same selected project, execution ID and immutable source hash.

Output acceptance requires bounded valid UTF-8 `FinalReport.md`, preserved original `FinalVerdict.json`, and strict `FinalVerdict.adapter.json` authenticated against one captured wrapper stdout digest and the actual original-byte hash. Only positive `Infinity` at the five retained profit-factor path families becomes null with an exact `positiveUnbounded` annotation. Original nulls gain no annotation, finite values and original verdicts remain unchanged, and unknown/non-supported non-finite values, overflowing literals, duplicate keys and malformed/missing files fail visibly. A known verdict and explicit missing evidence remain mandatory. Optional `outputProvenance` metadata carries original/envelope hashes, sidecar path and typed annotations; it does not upgrade the original verdict. See [the output adapter contract](VALIDATION-OUTPUT-ADAPTER.md). The adapter does not recompute or replace Python algorithms.
