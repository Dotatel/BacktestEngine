Optimize routing is the separate optimization lane.

## Settings behavior

`app-settings.json` schema v1 contains only a default export folder, update consent/dismissals/last successful metadata timestamp, and extension enablement bound to an imported manifest SHA-256. Missing storage is a distinct first-run state, with no immediate file write. Malformed, unsupported or oversized documents are preserved and block mutations. Recovery requires a separate explicit UI confirmation, writes a byte-preserving unique backup, then atomically creates offline defaults. It does not reset onboarding or touch project files.

All mutations serialize through the host mutex and use a same-directory synced temporary file. Settings input is bounded to 64 KiB, 200 extension identities and 50 dismissed strict SemVer versions. Native folder selection accepts an existing canonical directory outside internal run storage. The saved default is revalidated whenever Reports or an extension export opens its save dialog. Every export still requires the native save dialog and a new filename. Canceling a folder picker changes no preference.

Diagnostics display actual app/version/platform/local paths and engine/Python bundle presence. Presence is explicitly distinguished from successful runtime or trading compatibility.

## Experimental declarative extensions

The native folder picker imports only bounded validated `manifest.json` bytes and an integrity receipt into a new app-owned registry directory. It does not copy scripts or modify the original folder. IDs, text, strict SemVer, the supported API and permissions are validated; unknown fields, executable entry points, unknown contribution kinds, undeclared permissions, path escapes, collisions, symlinks/junctions/reparse points and oversized input are refused. The registry is bounded to 200 entries and each manifest to 64 KiB. Invalid/tampered registry entries remain isolated and visible with their actual error.

Import starts durably disabled. Enablement requires the reviewed hash and survives restart. The only native allowlisted actions are `report.export-json`, `report.export-csv` and `report.export-html`, with `commands` permission. These are names for the existing trusted report exporter; extensions cannot supply JavaScript, native code, arbitrary filesystem access or network grants. There is no VS Code extension compatibility claim.

Exports show and send the reviewed saved project's run ID and report hash. Native checks reverify enabled state, manifest hash, declaration/permission and host-selected run/report identity before and after the save dialog. A stale, disabled, tampered or foreign-run command fails. Renderer-supplied destination paths are not accepted. In-app uninstall/replacement is not implemented; collisions do not overwrite an existing registration.

## Manual release metadata checks

Release checks are disabled by default. Enabling stores consent and performs no request. Only an explicit **Check now** click performs the native HTTPS GET; there are no startup checks, background polling, automatic installation, restarts, signing, publishing or provider calls. Ordinary offline work has no network dependency.

The fixed source is `https://api.github.com/repos/Dotatel/BacktestEngine/releases/latest`. An explicit bounded read at `2026-10-24T10:42:52Z` returned HTTP 404 (144-byte GitHub JSON). This establishes source unavailability at that time; it does not establish that the installation is up to date or that no public release exists. The product reports unavailable public release information for 404, separate rate-limit/declined status for 403/429, and actual error states for offline, timeout, invalid or oversized responses. Failures never become up-to-date. Attempt timestamps are separate from the persisted timestamp of genuinely valid stable release metadata.

Requests use the maintained reqwest HTTPS client, no redirects, a five-second timeout, no retries and a 1 MB response cap. The request carries the app version/user agent and GitHub protocol headers, with no project data or provider secrets. Stable strict SemVer comparisons use the maintained semver crate and ignore build metadata precedence. Release notes are bounded to 2000 plain-text characters with control characters removed and rendered as escaped text. Only HTTPS `github.com/Dotatel/BacktestEngine/releases/...` URLs without credentials, nonstandard ports, queries or fragments are accepted. Windows asset URLs must use the same repository's release-download path. Browser opening and version dismissal require separate explicit clicks. No release availability is fabricated.

Approved direct reuse is the already locked `semver 1.0.28` and `reqwest 0.13.5` with default features off and `blocking,rustls`, running the bounded blocking request through Tauri's blocking task pool. Both crates are MIT/Apache-2.0 dual licensed. Official references: [semver Version](https://docs.rs/semver/1.0.28/semver/struct.Version.html), [reqwest blocking ClientBuilder](https://docs.rs/reqwest/0.13.5/reqwest/blocking/struct.ClientBuilder.html). Enabling the TLS/client feature closure resolved 47 additional locked transitive packages/features; this adds native dependency/build/binary cost. No package upgrade, Node runtime, local HTTP server or new frontend dependency is required. Actual combined executable size remains for the lead's next build to measure.
