# Validation output transport

The retained Python writer uses `json.dumps` with its default non-finite output behavior. Two retained profit-factor functions explicitly return positive infinity when gross profit is positive and absolute gross loss is zero or negative. Division can also overflow; the adapter records `positiveUnbounded`, without claiming an independent proof of no losses. The current source provides no intentional `NaN` or negative-infinity outcome. The adapter changes no engine source, statistical calculation, gate, verdict, Monte Carlo summary, original JSON bytes or Markdown bytes.

`src-tauri/optimizer-host/ValidationOutput.py` is app-owned code. Its future integration runs the original CLI once and then normalizes only its fixed native output inside the same isolated Python/process-tree boundary. It accepts separate argv entries for the preserved package root and absolute `validation` output directory, followed by the original CLI arguments. These paths must come from native host state, never renderer input. Rust embeds the same file with `include_str!`; the managed host can embed that exact file as an assembly resource. No additional Python packages are needed.

The wrapper preserves `FinalVerdict.json` and `FinalReport.md`. It writes an atomic sibling `FinalVerdict.adapter.json`, refusing an existing sidecar, then prints exactly one `BACKTESTENGINE_VALIDATION_OUTPUT_SHA256 <digest>` line. The envelope has exactly `version:1`, `originalSha256`, `payload` and `nonFinite`. Known positive-infinity leaves become null in `payload`, with separate annotations containing `pointer`, `token:Infinity`, `meaning:positiveUnbounded` and `origin:retainedProfitFactor`. Original nulls receive no annotation and finite statistics remain unchanged.

Only these exact field families support literal positive infinity:

- `/{combined_report,latency_report,walk_forward_report}/profit_factor`
- `/monte_carlo/distributions/<actual list index>/pf`
- `/monte_carlo/concentration/remove_best/<actual list index>/pf`

The stdlib parser identifies literal tokens using a private `parse_constant` result. Ordinary strings are never replaced. Duplicate JSON members, overflowing number literals such as `1e999`, `NaN`, negative infinity, non-finite values outside the allowlist, invalid known PF types and malformed JSON fail closed. Finite numbers and original nulls remain valid. Structural limits are depth 64, 8 million nodes and 500007 annotations (five methods times the existing maximum report-only Monte Carlo run count, four concentration shocks and three combined fields). Both original and normalized bytes are bounded to 64 MiB. `allow_nan=False` guards final serialization. These are transport limits; they do not expand the existing workflow budget.

`validation_output::verify(original, sidecar, captured_stdout)` returns `VerifiedOutput` containing `payload`, `original_sha256`, `envelope_sha256` and typed `non_finite`. It verifies one captured stdout marker, both actual byte hashes, strict envelope/annotation fields, bounded payload structure, unique canonical pointers into actual arrays and allowed nulls. A finite original payload must equal the sidecar payload exactly and cannot acquire non-finite annotations. For non-standard original JSON, the frozen trusted wrapper is the semantic authority for literal-to-null conversion; Rust does not contain a second permissive parser. Existing consumers must still validate selected-run inputs, original verdict/evidence vocabulary, scenario provenance and unchanged files. A sidecar alone never establishes trading or full-validation acceptance.

The original summary explicitly excludes positive-infinite Monte Carlo PF samples before computing `pf_p05`; an empty sample list yields its retained `0.0`. The adapter preserves that result. It neither relabels the original finite zero nor recomputes a quantile.

Seven standalone tests passed with the pinned staged CPython 3.14.9, including a fresh actual unchanged-CLI reproduction of all 23 infinite PF values from the retained economic-basket regression. The CLI fixture is synthetic and does not execute the C# engine. Raw output remains non-standard JSON while the sidecar retains its exact hash, verdict and Monte Carlo summaries. Evidence: `artifacts/validation-output-python-tests.log`. Seven Rust transport tests and the updated report-only native regression await the coordinated native batch. The report-only source now calls the shared wrapper/verifier; full-workflow consumer/managed-host embedding and staging belong to the validation integration owner. None of this changes the untouched owner review copy.

The implementation uses the documented Python 3.14 [JSON hooks and strict serialization](https://docs.python.org/3.14/library/json.html) and the platform's existing [assembly resource API](https://learn.microsoft.com/en-us/dotnet/api/system.reflection.assembly.getmanifestresourcestream?view=net-10.0).
