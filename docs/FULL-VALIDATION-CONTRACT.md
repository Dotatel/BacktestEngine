# Full validation backend contract

This is a backend increment. Retained `engines/**` sources and numerical algorithms remain unchanged. Existing report-only validation remains available for old successful runs. A full rerun requires new host-captured replay evidence; current settings, current source and an old report cannot reconstruct a missing receipt.

## Ownership and integration order

The execution QA lane owns new `replay_receipt*.rs`, `full_validation*.rs`, a separate generated validation entry, and the validation managed host. First implement/test these modules without enabling a command. Execution/preflight hooks wait for the ordinary-parameter audit writer to freeze. `lib.rs` module/command integration is coordinated with the lead/assistant owner. `OptimizationHost.cs` and `prepare-optimizer.ps1` remain with the candidate-binding audit writer until handoff; reuse its Job Object code only after that freeze. No frontend or retained-engine changes are part of this lane.

## Original contracts and limits

`ValidationEngine/Cli.py` accepts only `--config` and optional `--dry-run`. `BacktestRunner.py` builds `dotnet run --project <project> -- ...`, including strategy, parameter file, symbol/timeframe, repeatable ticks, profile, dates, commission, report path, skip-equity, spread/multiplier, optional max ticks/latency and sorted parameter overrides. It omits balance/slippage and bar-replay controls. It captures subprocess output itself without a timeout; the native owned process tree therefore needs the outer limit.

Cost stress expands symbols × source windows × spread multipliers × commission multipliers. Latency and walk-forward use only the first symbol. Walk-forward plans train/validation/test ranges with embargo but executes fixed-parameter test splits only; it performs no training or parameter optimization. Only test ranges contained by a configured data window become actual scenarios. The backend starts with one tick dataset, one symbol and one window, positive finite distinct multipliers, positive distinct latency values and a bounded nonempty set of contained walk-forward test splits. Bars are rejected before launch.

The Python CLI can read an existing report even when the corresponding subprocess failed. Native acceptance must independently require the complete expected scenario set, exact identities/owned paths, successful statuses/exit codes and strict complete original reports. `ExistingReports=[]`, `ReuseExistingReports=false` and a unique output directory prohibit reuse. Preserve the original PASS/FAIL/UNPROVEN result. Zero trades, non-finite serialized statistics and unavailable authentic authority are not repaired with synthetic trading values.

## Original-execution capture

At successful Build, record a private source manifest over the exact engine/strategy/generated-entry/project/restore-policy/receipt files used by that compilation, alongside approved DLL/runtime hashes. At execution, after normal preflight, freshly assemble the selected project and require its revision AND complete source manifest to equal the approved compilation evidence. Never trust mutable source left beside an old DLL. Snapshot all retained engine, strategy and generated entry files into the owned run before any future edits can change replay provenance.

After SDK probing, re-read/hash the registered dataset and write those exact bytes to the owned run. Execute that frozen path, then verify it again at completion. A changed catalog source cannot become the baseline input through the existing probe/read race.

The versioned receipt records original request semantics (including parameter-loading mode and explicit overrides), resolved symbol/timeframe, catalog IDs/hashes, starting balance/slippage/spread/commission controls, original date/row limits, actual source manifest, approved assembly/runtime hashes and frozen dataset/profile/registration/authority-byte records. Capture originals without editing them. Publish the receipt hash with last-good evidence only after accepted baseline completion; bind its source report hash separately to avoid a self-hash cycle. A missing receipt never silently falls back to current mutable inputs.

## Authentic authority containment

Freeze the derived profile and both registration JSON files, including the original imported profile's registered SHA-256. The original import file need not remain present: the engine consumes the registered derived profile. Discover only active C# authority relationships: profile specification source; active commission authority and its source events/report/specification; authenticated swap authority and its source report. Verify declared SHA-256 values, exact manifest binding and bounded file/count/aggregate sizes. Reject reparse-point ancestors and conflicting active relationships. Do not follow arbitrary JSON strings/URLs or copy an entire user directory.

Keep original absolute authority paths and preserve their bytes, including nested hash-bound JSON. Before baseline and each full workflow, open every required original with Windows `FILE_SHARE_READ` only, hash those opened bytes against the receipt, and retain the handles until all owned descendants exit. This prevents writers/rename/delete from changing active authority while the original engine reads it. Capture evidence bytes too. A later missing/changed original blocks reruns; the first receipt format is intentionally not independently relocatable. Non-Windows code must not claim Windows write/delete exclusion.

## Generated entry and process contract

A per-validation generated entry uses the existing reflection-forwarding pattern. It validates/removes only its exact host-owned placeholder `--params` argument, retaining the original baseline no-file parameter semantics; it forwards the captured overrides and scenario arguments and appends captured original balance/slippage. Applying a generated empty parameter file would instead run C# attribute defaults and can change the strategy. Reflection metadata defaults are not a substitute for constructor state. The entry is separately hashed, compiled from frozen source and identified as such; this is not identical-binary parity.

The native parent creates a random named Windows job with 16 active processes, 2 GiB committed job memory and kill-on-last-close. The managed host opens that existing job, assigns itself and immediately closes its temporary join handle before starting Python, leaving the native parent as sole persistent owner. Cancellation/timeout/overflow explicitly terminates that exact job, requires native ActiveProcesses zero and waits synchronization handles captured from job-reported members before termination. Windows job-accounting zero alone proved insufficient for complete process-object signaling in the actual regression. Enumeration is not atomic: this is not a claim that one PID snapshot exhaustively captures every possible process object created during an arbitrary concurrent spawn race. Normal associated descendants are terminated by the job; the actual known Python/dotnet child/grandchild handles must be signaled before return. A separate direct-host wait covers failure before job assignment. Unconfirmed cleanup retains engine/validation busy and authority/input handles until restart; future drop conservatively blocks reuse when direct-host acknowledgement is unavailable. Parent-death proof checks that the host's temporary join handle cannot keep descendants alive.

Resolve packaged SDK/Python/package/host assets by verified host paths, configure offline restore, disable compiler sharing/node reuse and isolate caches. The full host fixes the original public MSBuild environment properties Configuration=Release and UseAppHost=false, preserving baseline conditional-compilation behavior and direct dotnet/DLL launching. A synthetic actual-SDK sentinel checks the Release branch, executable identity and absence of a generated apphost; this does not establish binary or financial parity. Canonical private project IDs remain unchanged; existing workflow parent paths use lossless DOS/UNC tool spelling only after an exact canonical round-trip check, because MSBuild rejects verbatim project paths as wildcard imports. The producer boundary copies exactly 27 compile-time-pinned original Python sources into the owned workflow and locks the full 37-file pinned interpreter tree. The entire frozen producer/runtime object stays with prepared inputs through confirmed exit or cleanup-unconfirmed quarantine; full result provenance records original producer, wrapper, interpreter and staging identities. One scenario worker avoids unnecessary compiler descendants. No global SDK shutdown or user preview/profile action is part of this backend work. Root separately observed the historical preview PID absent; no cause is inferred from these scoped helper tests.

The shared app-owned output transport preserves original FinalVerdict JSON/Markdown bytes and hashes. Only literal positive Infinity at exact retained profit-factor paths becomes null in a separate strict JSON envelope, with authenticated positiveUnbounded pointer annotations. The original numerical verdict is unchanged. Unsupported non-finite values, exponent overflow, changed bytes and absent/duplicate stdout envelope digests remain failures.

Compiler membership is explicit in generated, hashed and locked Directory.Build.props/targets. Both native compile and original Python dotnet-run inherit fixed absolute DirectoryBuildPropsPath/DirectoryBuildTargetsPath, preventing ancestor/child policy shadowing. Before CoreCompile the target pins original runner/shim/strategy/entry source items and restores only the three exact SDK-generated obj inputs. Real SDK regression adds then removes valid runner/shim injections and child shadow policies while original source files are locked; neither injected type reaches the DLL and the postscan/fresh manifests remain equal.

Initial limits: 64 executed scenarios total, at most 8 values per stress axis, latency 1–1000 ticks, positive train/validation/test days, embargo 0–365 days, one worker, Monte Carlo 1–10000, seed 0–2147483647, overall 600 seconds (fixed host policy). Plan before spawning, with normalized UTC strings, checked arithmetic and no invented missing dates. The owned working tree is observed every 250 ms with 8192-entry, 20-level and 512 MiB limits. This observed disk budget can overshoot between scans; it is not an OS disk quota. Only transient NotFound for an enumerated output entry is tolerated, never a missing fixed root, permission error, reparse point or missing/changed frozen input/authority.

## Result publication and required checks

Full results bind canonical private project identity and host public display root, execution/receipt/source-report hashes, actual source/entry/compiled hashes, config/runtime hashes, exact scenario counts and hashes, original verdict/missing evidence, owned output locations and real lifecycle errors. Reuse the established coherent publication lock order; failed/canceled/stale jobs preserve prior completed evidence. Restore requires the same selected project and original source run/receipt/report identity.

Tests are explicitly synthetic boundary/process fixtures, not economic qualification: post-preflight dataset replacement; fresh-source versus approved-manifest mismatch; profile/registration and nested-authority tamper; Windows write/rename exclusion and release; unsupported bars; nondefault balance/slippage and no-file parameter adapter preservation; scenario bounds and original Python plan agreement; failed process with leftover report; missing/foreign/non-finite output; cancellation/timeout killing child/grandchild; exact receipt/report hashes and stale-project publication. Genuine positive validation remains blocked without genuine validated economics and authorities.
