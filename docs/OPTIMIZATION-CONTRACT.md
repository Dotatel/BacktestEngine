# Optimization adapter contract

The implementation targets the retained C# `BacktestEngine.Optimizer`, including its search generation, scoring, candidate parameter files and replay cache provenance. The legacy desktop workflow service was inspected: it mirrors generation/scoring in JavaScript and explicitly does not invoke the original optimizer CLI. That numerical duplication will not be ported.

## Host inputs and source binding

The renderer supplies a typed draft: approved strategy name, imported dataset/profile IDs, explicit timeframe/capital/cost/replay limits, typed base parameter values, a grid or seeded-random search with explicit candidate value arrays, and bounded candidate/worker budgets. It supplies no executable, project, output or arbitrary file paths.

The command binds the host-selected project to its approved build. Both ordinary replay and optimization call `execution::preflight_execution_inputs`, retaining receipt, main DLL, runtime companion, current source revision, strategy, dataset catalog and registered economics-authority checks. `ApprovedBuild.parameter_schemas` is captured from real compiler reflection and remains authoritative for every base/search parameter name, type, option and bound.

A fresh runner snapshot uses existing `workspace_build::assemble` after preflight and SDK probing. Its complete source manifest (including generated entry, project, restore policy and fixed source membership) and revision must match approval after the move to its final runner directory. Dataset size and SHA are checked again after the SDK probe. The existing replay capture helper freezes registered profile/registration bytes and all transitive authorities. Original authority paths stay private; captured copies, original authority handles and source files remain locked through confirmed teardown or native quarantine.

The original optimizer uses `build_runner=true`, then invokes `dotnet run --project <wrapper> --no-build -- <engine arguments>`. Fixed inherited public MSBuild properties `Configuration=Release`, `BaseOutputPath=bin/Debug/` and `UseAppHost=false` select one actual Release configuration DLL build without editing retained source or CLI arguments. The output is `runner/bin/Debug/Release/net10.0`: the legacy `Debug` base folder lets the unchanged original replay fingerprint discover the same actual DLLs, while the configuration remains Release. There is no duplicate output, copy, junction or alias. [MSBuild documents](https://learn.microsoft.com/en-us/visualstudio/msbuild/common-msbuild-project-properties) that the configuration is appended to BaseOutputPath. The actual rebuilt DLL is recorded separately from the earlier approved DLL; byte equality is not claimed. Every job gets its own app-owned output folder; no cache directory is destructively cleared.

The retained optimizer has no scenario slippage field. Nonzero execution slippage is rejected explicitly rather than silently omitted. Tick bid/ask input, explicit bar spread/price mode, commission sentinel/profile convention, symbol specification, inclusive start/exclusive end, bar period and replay limits are preserved. Initial search dimensions use finite explicit value arrays, avoiding a second range-expansion algorithm.

## Process boundary

The native parent creates the existing shared Windows Job Object with 16 active-process and 2 GiB committed-job-memory bounds. `OptimizationHost` joins that named parent job and immediately closes its temporary join handle before emitting one READY marker or invoking original Main. Native capture is bounded to 128 KiB per stream and 30 minutes. Completion, cancellation, timeout and output errors drain the owned job using kernel accounting plus signaled member handles, then confirm the direct host exit before releasing both workflow busy latches. Dropping the native future keeps the outer cleanup marker false: captured source/authority handles and both latches remain quarantined until restart. The native vector is `host --job <native name> -- --config <native path>`; only the private job envelope is removed before original Main. Verified SDK and workflow paths use the reviewed canonical-equivalent DOS/UNC spelling for MSBuild. Offline restore config, isolated caches, no-certificate/no-logo settings and disabled shared compiler/node reuse are inherited by original build/run processes.

Official platform references: [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [AssignProcessToJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject), [extended job limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information). Rust/Tokio custom process-attribute spawning remains experimental in the inspected APIs, so no nightly runtime or new package is proposed.

## Truthful output

Receipt v3 must match the single captured stdout SHA, private input-record SHA, approved source-manifest SHA and Release configuration. It requires exactly four actual compiled runner hashes at `runner/bin/Debug/Release/net10.0`: `WorkspaceCompile.dll`, `BacktestEngine.CAlgoShim.dll`, `WorkspaceCompile.deps.json`, and `WorkspaceCompile.runtimeconfig.json`. Native verification locks those exact files before parsing any original numerical result. The original cache fingerprint hashes the actual DLLs; native binding additionally covers both JSON companions. Receipt v2, missing files and changed hashes fail closed. `results.json`, each `candidate_result.json`, reports and generated presets retain their whole-byte hash bindings. An interrupted host without an authenticated v3 receipt exposes only unproven, non-numerical records; build failure does not receive placeholder compilation evidence.

Candidate rows come only from actual optimizer artifacts. Failed or incomplete candidates show no invented zero-valued metrics. JSON reads are bounded to 64 MiB. Candidate/report/preset paths must match the exact native output folder; redirected source files are rejected. Completed reports pass the existing strict execution parser, strategy/symbol matching and unchanged-byte hash checks before their metrics are exposed. After interruption, only actual persisted `candidate_result.json` records are read; unstarted candidates are not synthesized. Search is in-sample exploration, not strategy qualification or an automatic recommendation.

Native report drawdown and full replay drawdown remain distinct. The original optimizer's unbounded-profit-factor scoring convention uses a `999` sentinel; that must not be presented as an ordinary observed profit factor when the source report leaves it undefined. No scoring formula is recalculated in Rust or TypeScript.

## Current acceptance

Native commands/state and the optimizer resource map are registered. `scripts/prepare-optimizer.ps1` builds four unchanged original optimizer sources plus the process host with the verified bundled SDK and clear package feeds. It stages fixed DLL/dependency/runtime-config filenames with SHA-256 metadata and license material using a guarded component rename/rollback. The numerical sources under `engines/**` remain unchanged.

`OptimizeStage` is mounted in the workflow with injected optimization/execution bridges and current build/parameter identity. It presents imported input selection, bounded grid/seeded-random settings, exact typed JSON value arrays, honest process states/cancellation, and actual candidate/provenance records. Native IPC, catalog reads, stale responses and duplicate-launch guards live in the hook. Browser preview produces no candidate evidence. Last-good evidence is session-scoped on the host, filtered by selected project, approved revision and artifact hash; original saved files remain on disk. This is not a durable run registry.

Accepted focused evidence:

- `artifacts/optimizer-host-tests/ff0e2f8490c7479c9dc46d5f072bfaf6/result.json`: actual Windows Job Object fixture preserves ordinary exit codes 0/2 and kills a real child/grandchild tree after terminating only the owner. It is a synthetic lifecycle fixture, not an engine report.
- `artifacts/optimization-native-tests.log`: eight native tests pass, including strict saved-source/hash/path/undefined-statistic adaptation, interrupted record binding, staged host hashes, genuine unchanged optimizer exit 2 from an explicitly synthetic failing runner, and actual optimizer cancellation after its real runner descendant starts. The cancellation regression checks that descendant termination within a bounded post-cancellation kernel query. No test is skipped.
- `artifacts/optimization-clippy.log`: all-target Clippy with warnings denied passes. Frontend form/hook/stage DI fixtures and light/dark 1920/800 px browser accessibility/overflow checks are synthetic; captures are under `artifacts/optimization-ui-review`.

Reflected schema checks constrain the draft; they do not establish numerical or replay parity. Actual parameter execution and scoring remain authoritative in the original C# engine/optimizer. The genuine economics authority bundle is unavailable, so positive real-data optimization and full qualification remain unproven. Full rebuilt native/installer workflow acceptance is coordinated separately; existing earlier installer evidence does not cover this new module.
