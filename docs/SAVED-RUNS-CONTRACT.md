# Durable saved-run backend

The `saved_runs` modules are connected to native execution and async IPC in source, awaiting the coordinated verification checkpoint. They do not run an engine, rebuild a strategy, infer missing inputs or restore serialized financial metrics. The initial nine storage tests use explicit synthetic files and an injected parser that supplies no financial results. Additional integration tests use the production strict parser over explicitly synthetic, zero-trade ReportWriter-shaped JSON; neither fixture class establishes C# trading proof.

After the existing engine exit, complete report parsing and replay-receipt verification succeed, `commit_successful_run(state, project, result)` creates one `runs/<native UUID>/completion.json`. It holds actual output/receipt/input file handles read-only against Windows writes/deletes, hashes each actual artifact, flushes a same-directory `NamedTempFile`, then uses `persist_noclobber`. Existing records and artifacts are never overwritten. The function does not publish last-good or write a selection pointer.

The record contains schema version, UUID, private canonical project, original process timestamps/duration/bounded log, report identity/build/dataset metadata, and fixed-name SHA-256/size records for `report.json`, `trades.csv`, `open_positions.csv`, optional `equity.csv` and `replay-inputs/receipt.json`. Skipped equity is explicit absence; a later unexpected file is rejected. Account metrics, parsed trades, equity points and reconstructed requests are absent from the completion schema. Unknown fields are rejected.

A commit error is distinct from an engine failure: `SavedRunCommitError` says **Engine completed; saved-run record could not be committed**. The execution integration retains artifacts and the prior selected result, reports the durable-save error, and does not silently rerun the engine or return a fabricated financial failure. It moves the owned result through `spawn_blocking`, commits before last-good publication, and avoids cloning its financial vectors merely to inspect metadata. The typed original `ProjectRoot` is captured by the command before any await and retained through completion. Completion creates history; the durable selection pointer changes through explicit saved-run selection/recovery.

The existing replay receipt already preserves the exact original dataset/profile, registration JSON, frozen source/project/NuGet/revision tree, approved assembly and three CLR companions, and transitive authority copies. Historical view checks only these captured copies; it never opens the receipt's original authority/source/catalog paths. It verifies the exact captured source manifest and mandatory roles, including both fixed Directory.Build policy files. Every manifest source must have an exact matching hash/size in the receipt's retained-lock inventory before source walking. Full validation or another rerun keeps its separate live-original-authority preflight. A vanished original therefore does not invalidate an intact historical view, and copied historical evidence does not bypass future rerun requirements.

`list_saved_runs` derives pages from actual native folders without a global rewritten index. It uses one project-bound opaque `ReadDir` cursor, with at most 100 rows and 1024 examined entries per call and a five-minute lifetime. A fresh scan explicitly invalidates the earlier ephemeral cursor; expiry returns an error. There is no total history cap, background eviction or deletion. Ordering follows live filesystem enumeration, not globally sorted completion time. Refresh starts a new scan after concurrent changes. Rows are labelled `recordedNotOpened` and carry no financial values. Broken/unassigned evidence is counted and diagnosed without guessing project ownership; diagnostics themselves are bounded, with an explicit additional-issue count.

Selection accepts only `{projectRoot,runId,completionSha256}`. `projectRoot` must equal the host-issued public identity of the currently selected project; it is never opened as a renderer path. The native UUID selects exactly one app-owned run directory. The completion SHA binds the selected catalog row. All paths are fixed names or checked receipt-relative components, with reparse/stream/traversal checks before reads. Completion metadata is at most 256 KiB, receipt JSON 4 MiB, individual outputs/frozen files 64 MiB and captured inputs 1 GiB aggregate, with at most 4104 ordinary captured files, 4096 source files and 16 authorities. Empty original source files remain valid; required output/receipt artifacts cannot be empty.

Only `NotFound` is accepted as absence. Skipped equity, an absent pointer and a first-install missing run root use the same strict metadata boundary; permissions, I/O failures, redirected ancestors and non-directory ancestors produce errors. A deterministic injected metadata-error test covers these branches without changing Windows ACLs. No `exists()` failure is converted into empty history or absent evidence.

`select_saved_run` authenticates completion, every output and the strict replay receipt/captured copies, then calls a native-only `RestoreParser` function pointer while all inspected handles remain locked. The seam receives a metadata-only seeded `ExecutionRunResult`, the verified receipt, and exact report/run paths. The execution owner must reuse strict `apply_report` with that seed and folder, check report/receipt baseline controls without live authority I/O, and retain exact metadata/hashes. The blank-identity `parse_report` convenience function is not this production seam. The saved-run module verifies returned identity, paths, hashes and the existing Reports source verifier again. Only that parser may supply numerical result sections. Frozen settings and provenance are returned separately from the receipt; public DTOs strip canonical project and original authority/source paths.

Publication rechecks current project, execution idle state and the original coherent last-good slot. It locks selected project, execution running state, last-good canonical project, then last-good result, with no await. The only I/O in that short publication transaction is the bounded atomic pointer save. `run-history/<SHA256 of canonical project>.json` contains only version, canonical identity, UUID and completion SHA. The pointer is flushed and replaced atomically before the infallible in-memory slot update. Invalid evidence, stale/busy project/run, parse failure and pointer write failure preserve the old pointer and last-good result. Concurrent selection that changes the slot is detected. `restore_selected_run` uses the same original snapshot across pointer read and full verification, and never guesses a most-recent record. Missing pointer means no saved selection; malformed pointer is an error, not a reset.

Opening/recovery uses one per-state RAII single-flight latch acquired before project snapshots or disk reads. A second call fails busy before hashing or parsing, so concurrent callers cannot multiply the per-call 1 GiB/4104-file budget. Every success/error path releases this latch. Catalog enumeration has its separate single bounded cursor. Native integration must use async Tauri commands and dispatch these synchronous filesystem operations through `spawn_blocking` with app-managed state, keeping verification off the UI thread; [Tauri's command documentation](https://v2.tauri.app/develop/calling-rust/#async-commands) explains the synchronous main-thread behavior. No new queue or store framework is required.

Legacy/orphan folders without a completion record remain unproven. A crash before the create-only commit may leave genuine raw artifacts without proof of accepted completion; the backend does not fabricate history by backfilling a record from those files. Ordinary SHA checks detect corruption and mismatches. They do not cryptographically authenticate against an owner rewriting every record, pointer, artifact and hash together; no protected external signature anchor is claimed.

Source integration registers/manages `SavedRunState` under the authoritative native workspace roots and exposes async list/select/restore-selected commands. `execution::restore_frozen_execution` uses seeded `apply_report`, exact completion hash and the shared pure baseline-control verifier; it clears numerical sections before parsing and never borrows a mutable original input. Saved log validation matches the existing producer's 12,032-character published bound, including truncation-marker headroom. No saved-run UI is added.

Thirteen synthetic storage/parser tests are now supplied. The four added cases cover production strict parsing and explicit pointer recovery without originals, malformed/control-mismatched reports preserving the previous pointer/result, missing locked source inventory, and the published log boundary. SDK probe storage also now derives from the already managed workspace build root, preserving isolated native profiles instead of consulting a separate default app-data root. Rust formatting checks passed; the combined Cargo run and actual rebuilt-app IPC acceptance remain pending. Genuine economic execution and trading parity are not claimed.
