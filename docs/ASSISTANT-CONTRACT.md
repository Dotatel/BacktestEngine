# Optional assistant contract

This feature uses the existing registered OpenCode Desktop CLI and its normal background-service discovery. It does not configure credentials, billing, fallback models, global permissions or another server. The local engine, validation, optimization and reports remain independent of it. No assistant answer is applied to source, executed, or treated as backtest/qualification evidence.

## Existing code and research decision

The retained `direct-integration/desktop/services/assistant-service.mjs` and its injected tests were inspected. Their owned deny-all agent/session, local history and explicit text-context ideas are reused. Their paid Go model allowlist is excluded. Their polling of the last assistant answer is replaced with exact native-admitted user-ID binding and a successful idle boundary. The standalone app's `agents.rs` already discovers the Desktop-managed CLI; integration will reuse that resolver rather than introduce another discovery path. No new package is needed.

The installed CLI reports version 2.1.4. Read-only metadata checks confirmed the two allowed routes, `opencode/glm-5.3-flash-free` and `opencode/deepseek-v4.1-flash-free`, enabled and active with zero input, output, cache-read and cache-write prices. These observations are not a permanent price guarantee. The adapter fetches current metadata in its own location before every send, requires all nonempty price tiers to have those exact finite zero prices, and rejects missing/unknown charge fields. Selection is explicit; a missing, disabled, limited or paid route never invokes a fallback.

Official API/config sources: [OpenCode V2 API](https://dev.opencode.ai/v2/docs/api), [permissions](https://dev.opencode.ai/v2/docs/permissions), [agents](https://dev.opencode.ai/v2/docs/agents), [models](https://dev.opencode.ai/v2/docs/models), [instructions](https://dev.opencode.ai/v2/docs/instructions). The retained local `artifacts/opencode-openapi.json` was checked for the installed V2 request/response shapes. CLI cwd alone did not reliably bind metadata location in the read-only probe; an explicit encoded `location[directory]` query did, and the adapter verifies the echoed canonical location.

## App text and inherited provider context

Only pasted text or an explicitly clicked in-memory context block enters a draft. The assistant does not read strategy source, report files, trade files, datasets, user OpenCode configuration, credentials or arbitrary renderer paths. Four context blocks are supported, each at most 100 label bytes and 2,000 text bytes; the question allows 8,000 UTF-8 bytes, and the composed application prompt allows 20,000. UTF-8 byte limits are intentional.

Saving a draft returns a native-composed exact preview, SHA-256 and monotonic conversation revision. `assistant_send` receives only the local conversation ID and reviewed revision/hash. It reloads the persisted draft and refuses any change after review. The UI separates Review from Send and revokes review when message, context or model changes. No file/agent/skill attachment is supplied to the prompt API.

The preview covers application text, not the provider's entire context. The panel explicitly discloses that OpenCode and the selected provider receive the reviewed text; earlier approved messages can remain in the conversation; existing OpenCode global instructions can apply; and the app cannot show all provider context. The official instruction documentation confirms that an isolated cwd does not disable global instructions. This adapter does not claim an isolated sandbox or weaken global settings to approximate one.

## No-tools and ownership boundary

The only local profile is app-owned `assistant/context/opencode.json`, using the current V2 plural `agents` key. It defines one proposal-only primary agent with a fixed system message, `steps: 1`, and exactly one permission rule: `{ "action": "*", "resource": "*", "effect": "deny" }`. Hand-edited profile drift is refused, not silently rewritten. Existing global profiles are untouched.

Before every prompt, including a continuation, native code verifies the registered agent, current free model, canonical location, provider session ID, native local-conversation ownership marker, no parent session, selected model, agent and exact single session deny-all ruleset. Provider IDs are private host observations; IPC does not accept them from the renderer. A provider session is created only by an explicit Send after review. Read-only Connect checks the existing service and metadata without creating a session.

Registered `Agent.Info.permissions` is a composed array, not the raw profile. Actual read-only QA found builtin allow/ask rules before the owned wildcard deny and a plugin deny after it. Official V2 last-match semantics permit a narrow proof: require a bounded array of exact three-string rules with known effects, locate a universal deny, and require every subsequent rule to deny. Missing/malformed/unknown rules or an allow/ask after that deny fail closed. No general permission matcher is reimplemented. The local profile and `Session.Info.permissions` still require the exact single deny rule. The initial failed single-agent-array proof is preserved at `artifacts/assistant-readonly-qa/f2473d5e255a41c98d595b73288fcef6/safe-projection.json`; successful composed-agent proof is at `artifacts/assistant-readonly-qa/4f84efc887d14694a62b67aadb0442aa/safe-projection.json`. Both made zero session/prompt calls. Fetching models before the agent initializes a fresh location's registry; an unready or unverifiable registry still stops the operation.

Provider responses must follow the exact native-generated `msg_…` user ID in the bounded latest timeline. An old answer, other user/control activity, changed model/agent, tool part/tool-call finish, changed-file snapshot, unexpected charge, empty/truncated/error answer, or absent successful idle marker is not accepted as a completed proposal. Reasoning and raw tool payloads never enter UI/local history.

## Persistence and cancellation

Local conversations use native UUID filenames under app-owned storage. Reads/writes validate ownership, schema, sizes and ancestor reparse points. A retained Windows file handle with no sharing prevents another app instance from writing the same assistant history; the OS releases it on process exit, without a stale lock-file deletion routine. This optional store is opened lazily and cannot prevent offline core startup. Writes use a same-directory temporary file and atomic replacement. Draft saves use optimistic revisions; UI saves are serialized so a late acknowledgement cannot replace newer editor text. Limits are 20 conversations, 100 messages and 1 MiB per conversation. Reaching a limit preserves existing files; no automatic deletion or eviction occurs. Incomplete local drafts can persist, but sending requires complete reviewed text/model/context.

Only one send is admitted at a time. CLI requests have bounded deadlines, stdout and stderr; raw metadata, provider headers/settings/body and diagnostics are discarded, not returned in errors. Native prompts are never automatically retried. A pending inbox ID is stored before prompt admission, so ambiguous timeout does not cause duplicate delivery.

Cancellation removes only that owned pending inbox input, interrupts only that owned session with `resume=false`, and waits for the service's idle acknowledgement. A proven pre-dispatch CLI failure is distinguishable from an ambiguous durable POST. An ambiguous POST remains blocked until its exact native input ID is observed in the owned timeline/inbox and then stopped; an idle/no-op interrupt alone cannot exclude delayed admission. Admission acknowledgements must match the exact reviewed text, delivery and empty attachments. Recovery reserves the active slot before reloading its latest record, so it cannot overwrite a newly completed answer with an older pending snapshot. Stopping remains possible if policy/model drifts after ownership is proved; such drift still prevents any prompt. A failed interrupt/idle/admission confirmation retains pending state and blocks another send, including after restart. Killing the CLI process alone never proves provider cancellation. Drafts and local history remain available.

## Current acceptance boundary

The six native commands and app-owned state are now registered, reusing the existing CLI resolver. The temporary path-include test harness has been removed so tests run through the production module. Workspace/rail/Panel mounting remains deferred. Native send tests use synthetic metadata/session transports and owned temporary storage; frontend tests use synthetic bridges. Actual safe read-only metadata QA verified the registered proposal agent, location/system/steps/effective deny-all and the two current free offers. No live session has been created and no model prompt has been sent in this implementation lane. Session permission readback, user-click Send, provider interruption and final rebuilt-app acceptance require the lead's explicit QA authorization. Read-only metadata observations do not prove successful generation or absence of every provider defect.
